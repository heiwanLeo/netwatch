# Netwatch

适用于 macOS 和 Clash Verge / Mihomo 的本地网络质量监控面板。通过一个网页观察网络延迟、节点质量，并在用户开启策略后辅助选择连接。

**当前状态：实验性项目。** 节点切换及基础监控已在 macOS 上验证；Wi-Fi 切换依赖系统授权、钥匙串和实际无线环境，不保证适配所有网络。

本机 Web 工具：分别观察基础网络与 VPN 节点的延迟、波动和质量评分，按你设定的分数选择连接。

## 启动与停止

首次使用先运行 `python3 native/build.py` 构建 Wi-Fi 辅助程序。然后在 Finder 中双击 **启动 Netwatch.command**，打开 <http://127.0.0.1:8766>。关闭网页后后台服务仍运行，双击 **停止 Netwatch.command** 可停止服务及 Wi-Fi 辅助程序。运行依赖 macOS、Python 3 和已运行的 Clash Verge / Mihomo，不需要 Docker 或 npm install。

```sh
python3 launcher.py
python3 launcher.py --stop
```

## 两层自动选择

- **VPN**：看当前节点评分，点击「测全部节点」查看排序；可手动切换到指定节点或最快节点。开启 VPN 自动选择后，当前节点最近 15 分钟的质量评分连续两轮低于所设阈值时寻找替代节点。切换前复测，复测失败保留当前节点；候选复测预估分须达到阈值且至少高 10 分，并受冷却时间限制。
- **Wi-Fi**：首次运行没有预设候选。先连接常用 Wi-Fi，程序会观察连接并在满足学习条件后加入候选；也可在页面手动允许已观察到的网络。当前网络质量连续 3 轮低于所设分数时，才考虑另一个附近可见、近期已验证的候选。连续确认连接中断时，也只尝试有足够良好历史记录的可见候选。候选至少有 10 次 24 小时内的真实探测，其历史评分需达到阈值且高于当前至少 10 分。不会将未连接 Wi-Fi 的信号强度当作实测延迟。
- **习惯学习**：记录本工具运行期间实际确认连接到每个 SSID 的时间。默认累计 30 分钟、至少 5 次探测且质量分不低于 70 时，自动加入候选。页面可改学习时间，或手动取消候选；手动取消的网络不会再被自动加入。
- **切换后验证**：Wi-Fi 切换后进行 3 轮、共 6 次基础网络复测。分数不达阈值或未改善，会尝试回到原网络；回退失败会明确提示。若发现你已手动选了第三个网络，则保留你的选择。

两个自动开关初次安装默认关闭。你可分别设置 Wi-Fi 和 VPN 的分数阈值与冷却时间。未授权、样本不足、无合格候选或候选不可见时不会盲目切换。

## macOS Wi-Fi 权限

点击「允许 Wi-Fi 读取」，在 macOS 系统提示中允许 **Netwatch Wi-Fi** 使用定位服务。苹果将 SSID 与 Wi-Fi 扫描结果归入此权限；程序不会请求地理坐标或上传位置。若拒绝，需要在系统设置 → 隐私与安全性 → 定位服务中启用。未允许时，物理网卡绑定的基础网络探测、按网关隔离的统计、VPN 监控和节点选择仍可用；Wi-Fi 名称、附近候选、习惯学习与自动切 Wi-Fi 处于未就绪状态。

本机 Swift 辅助程序通过 CoreWLAN 连接已保存网络。密码只通过 macOS Wi-Fi 钥匙串 API 在内存中交给系统，不记录、不写入文件、不放进命令行或返回网页。系统可能要求钥匙串确认；若系统没有保存密码，请先手动连接该网络一次。个人热点还需处于可发现状态。无法保证所有 macOS 版本、WPA 企业网络或 Instant Hotspot 的切换行为一致。

修改原生程序后重新构建：

```sh
python3 native/build.py
```

构建需要先安装 Apple Command Line Tools（可运行 `xcode-select --install`）。原生应用使用本机临时签名，未发布到外部网站。辅助程序状态会核对真实进程是否存活，停止时清理旧命令，避免重启后误用过期状态。

## 延迟、波动与统计

- **基础网络**：macOS `IP_BOUND_IF` 将 TCP Socket 绑定到物理网卡，绕过 TUN 路由。主卡与图表为 `223.5.5.5:443` 两次成功 TCP 握手的中位数；`1.12.12.12:443` 为独立参考，显示在检测详情。无法确认绑定时显示不可用，不静默退回经过 VPN 的探测。
- **路由器**：绑定同一网卡 Ping 默认网关，每轮 3 次，显示平均 RTT 与 ICMP 丢包。
- **VPN**：调用 Mihomo 节点 delay API，经指定节点访问统一检测地址，包含代理协议连接与 TLS/HTTP 等耗时。
- **近 15 分钟**：显示均值、总体标准差、P95、最低／最高、失败率与样本数。直连均值使用单次 TCP 原始探测值；VPN 使用周期探测值。
- **超时**：单独计入失败率，不作为零毫秒参与均值。Clash 管理接口不在线的时间不算节点探测失败。单个检测地址超时也不代表该节点所有网站都不可用。
- **P95**：最近秩法第 95 百分位，表示 95% 成功探测不超过该值。少于 20 个成功样本时仅供参考。

TCP、ICMP、HTTP 是不同测量方法，分别观察，不直接相减。历史保留 7 天，图表展示当前网络最近 240 轮。休眠、程序停止或权限不可用的时间不会凭空生成样本。

## 评分公式

0～100 分，越高越好。这是本项目可解释的启发式质量指标，不是运营商认证标准。

- 成功率：权重 40%，`100 - 失败率`。
- 平均延迟：权重 25%。
- 波动（标准差）：权重 20%。
- P95：权重 15%。

延迟维度在以下上下限之间线性扣分，低于下限得 100，高于上限得 0。直连：均值 50～800 ms，标准差 15～400 ms，P95 100～1600 ms；VPN：均值 200～1800 ms，标准差 40～650 ms，P95 400～3000 ms。代码在 `quality.py`。

至少 5 次实际探测后评分；窗口内只有 1 次成功记录时，标准差可能为 0，须结合失败率与样本数理解。当前 VPN 多维评分来自连续周期探测；候选节点切换前复测仅能提供即时预估分，不会伪造其长期波动数据。

## 不同 Wi-Fi 分开统计

优先用真实 SSID 加网关识别网络，权限不可用时使用物理网卡与网关地址／MAC。基础网络与 VPN 历史均按网络隔离，VPN 还按节点、节点组与检测地址区分。切换网络时丢弃旧节点测速、重置异常计数；回到旧网络可以继续查看它的历史。也可在顶部手动给网络命名。

系统隐藏 SSID 且两个 Wi-Fi 共用相同网关 MAC 时，无法仅凭网关区分接入点或频段；允许 Wi-Fi 读取后才能进一步区分 SSID。没有网络标识的早期调试记录不并入当前网络。

## 本地数据与代码

只监听 `127.0.0.1:8766`。写入接口校验本机 Host、Origin 和随机请求令牌。Clash 通过现有 Unix Socket 接入，不复制订阅或节点密码，不修改订阅、规则或运行模式。全局模式应操作 GLOBAL，规则模式应选择实际使用的节点组。不会主动关闭已有代理连接。

- `server.py`：探测、统计、HTTP 服务、Clash 选择。
- `quality.py`：质量分与候选即时预估。
- `wifi.py`：候选、习惯学习、切换验证与回退。
- `native/`：CoreWLAN 辅助程序源码与本机应用。
- `static/`：中文页面、实时图表、策略操作。
- `tests/`：策略、权限、隔离、统计和失败保护测试。
- `data/`：本机数据库、日志、辅助程序通信状态；目录仅当前用户可访问，不纳入源码包。

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
```
